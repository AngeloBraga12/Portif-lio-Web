# Engineering Context

This repository is maintained as a real portfolio product, not as a generated template.

## Working assumptions

- The current Netlify production experience is the visual reference until a newer source snapshot is explicitly established.
- Preserve the existing visual identity unless a change has a clear product reason.
- Content should be easy to replace without restructuring the page.
- Accessibility, responsive behavior and graceful failure are release requirements.
- Links and project metadata should point to real destinations; never invent project facts.

## Proactive implementation rules

When implementing a request, infer the missing low-risk details from the existing design and codebase. Prefer the smallest coherent change that completes the user's intent rather than asking for every implementation detail.

Before changing visual structure, inspect the existing hierarchy and preserve spacing, typography and interaction patterns unless the request explicitly changes them.

Before adding a feature, consider mobile behavior, keyboard access, reduced motion, empty states, invalid input and failure states.

## Content model

Project cards, contact details and professional links are content. Keep them easy to update and avoid duplicating the same fact in multiple unrelated places when practical.
